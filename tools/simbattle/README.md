# tools/simbattle — боты-атаки и win-rate по эталонным базам (QA-2)

Модуль `qa`. Играет бои через настоящее ядро `sim` (`sim.Battle.Apply`, то же, что считает сервер) боты-атаки против
16 эталонных баз `content/reference_bases/` (HQ1…HQ10 plain + coastal HQ5…HQ10) и считает win-rate по составам.
Критерий (`docs/01-architecture.md` §11, `modules/qa/CONTRACT.md`): ни один состав не > 65% и не < 30% против
эталона своего HQ.

## Запуск

Из корня репозитория (Go 1.26+; Windows: `C:\Program Files\Go\bin` в `PATH`):

```bash
go -C tools/simbattle run . -seeds 20            # все 16 баз × все составы × 20 сидов → tools/simbattle/out/
go -C tools/simbattle run . -bases hq05,hq10_coastal -strategies mixed,armor -seeds 5
go -C tools/simbattle test ./...                 # тесты бота (-short — быстрее)
```

Это отдельный Go-модуль (`tools/simbattle/go.mod`, `replace` на `../../sim` и `../../server`), поэтому в корне нет
`go.work` и сборки `sim/` и `server/` не затронуты. Грузит контент теми же функциями, что сервер:
`raid.LoadContent`, `FullSnapshot`; лог каждого боя проверяется `raid.Verify` в тестах.

| флаг | значение |
|---|---|
| `-seeds N` / `-seed-base S` | боёв на ячейку (база × состав), первый сид (по умолчанию 20 / 1) |
| `-bases` | `all` или список: `hq05,hq10_coastal` |
| `-strategies` | `all` или список: `rifle_mass,direct,hq_rush,ranged,armor,mixed,airborne,naval` |
| `-levels` | политика уровней атакующего: `parity` (по умолчанию) · `research` · `one` |
| `-garrison` | `rifle` (бункеры полны стрелками, по умолчанию) · `none` |
| `-win-stars` | сколько звёзд считать победой (по умолчанию 1) |
| `-turn-cap` | лимит ходов бота (по умолчанию 25), затем `Retreat` |
| `-out` | каталог отчёта (по умолчанию `tools/simbattle/out`, в `.gitignore`) |
| `-check` | код возврата 1, если sim отверг хоть одну команду бота |
| `-assumptions`, `-strategy-file` | заменить `assumptions.yaml` / `strategies.yaml` |

Выход: `out/report.md` (матрицы, подробности по ячейкам, причины провала, допущения), `out/report.json` (все числа),
краткая таблица в stdout. Одинаковые флаги и сиды дают побайтно одинаковый отчёт (число воркеров не влияет).

## Как играет бот

* Состав (`strategies.yaml`): проценты бюджета housing (лагеря → пехота; гараж → техника и корабли; Центр поддержки →
  заклинания) с jitter ±20% от сида. Юнит доступен, если выполнены `unlock` из `troops.yaml` (HQ и уровень казармы /
  завода / верфи в этой базе); `armor`, `airborne`, `naval` бывают «n/a» на низких HQ и на карте без воды.
  Герой — из `b_command` базы.
* Развёртывание: берёт сторону каймы, откуда HQ дешевле достичь (стены считаются штрафом), сид выбирает 1-ю/2-ю/3-ю по
  цене и сдвигает точку; тяжёлые юниты встают первыми; корабли — на воде каймы; десантники — как можно ближе к HQ в
  пределах `paradrop_edge_cells`; пассажиры грузятся в БТР / десантный катер.
* Ход: заклинания (авиаудар, ЭМИ, аптечка, адреналин, дым, пролом стены на пути), способность героя, затем каждый юнит
  от переднего к заднему: цели ранжируются по режиму (`nearest` / `hq` / `fav` — поле `fav` юнита), путь —
  Дейкстра по клеткам с теми же правилами движения, что у sim (диагональ, проволока, вода, чужие юниты); стена или
  забор на пути — препятствие, цена обхода = число ходов, за которые юнит её сломает × его скорость, так что бот
  идёт в ворота, когда это дешевле. Медик / ремонт лечат, диверсант глушит, БТР и катер высаживают пехоту.
* Бот видит только `sim.State` (клиентский вид: без скрытых ловушек).
* `Retreat` — по лимиту ходов или если 3 хода подряд никто не мог действовать (причина `stuck`).

**Сид.** Правила sim не используют случайность (спека §1.6), поэтому сид варьирует выбор бота: сторона высадки и сдвиг,
jitter состава. Бой с тем же сидом всегда тот же.

## Допущения (ASSUMPTION, `assumptions.yaml`; в PR — OQ-QA2-*)

1. **Лимит армии.** Контент даёт только «4 лагеря × 20 на L1 → до 280 housing к HQ10»: вместимость лагеря линейно от 20
   (L1) до 70 (макс. уровень); гараж — та же шкала; Центр поддержки — 10 housing заклинаний.
2. **Уровни атакующего.** `parity` — уровень = HQ (как уровни построек эталона). Прогрессии уровней в контенте нет
   (`research.yaml` — 12 узлов); результат от этого допущения **сильно зависит** (см. PR).
3. **Лимит боя.** 5 мин реального времени ≈ 25 ходов (≈ 12 с на ход, OQ-CONTENT4-1); по лимиту бот делает `Retreat`.
4. **Гарнизон.** Источника нет (OQ-RAID0-6): бункеры полны `u_rifleman` уровня казармы обороны.
5. **Победа** = не менее 1 звезды (≥ 50% разрушения); в отчёте также доли ≥ 2★ и 3★.
6. **Заглушки в контенте.** Урон обороны не растёт с уровнем (OQ-RAID0-2, SIM-8 в очереди) — баланс высоких HQ смещён.

Боты проще человека (нет игры строем, фокуса, ловли скрытых ловушек): низкий win-rate — нижняя оценка, высокий —
сильный признак слишком лёгкой базы.

## Структура

`env.go` — загрузка контента и эталонов · `army.go` — состав и лимиты · `bot.go` — бой, развёртывание ·
`actions.go` — поведение юнитов · `spells.go` — заклинания и герой · `world.go` — карта и поиск пути ·
`report.go` — агрегация и отчёты · `main.go` — CLI и пул воркеров.
