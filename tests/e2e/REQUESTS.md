# Запросы qa к другим модулям (QA-1)

`docs/open-questions.md` принадлежит design/orchestrator и не входит в OWNS qa, поэтому запросы — здесь; перенесите в
open-questions при мерже.

1. **ops — CI-job `e2e`.** Добавить в `.github/workflows/ci.yml` job по плану из `tests/e2e/README.md` («Запуск в CI»):
   compose up `--wait`, `npm ci` + `playwright install --with-deps chromium`, `npx playwright test`, загрузка
   `playwright-report`/`test-results`/`screenshots` как артефакта. Время прогона ≈ 1,5–2 мин без сборки образов.
2. **server-core/ops — тестовый хук времени (необязательно).** Сейчас e2e не может дождаться завершения долгой
   стройки (10 мин и больше) и проверить результат (уровень, освобождение строителя). Нужен dev-only способ:
   например, `FIRELINE_TEST_CLOCK=1` и `POST /v1/test/advance {seconds}` (только при включённой переменной, не в проде),
   либо `RATE`-подобная переменная масштаба времени для таймеров базы. ASSUMPTION: пока обходимся 1–2-секундными
   постройками (проволока) и проверкой таймеров по API.
3. **base — тестовые id.** Для устойчивости селекторов желательно `data-testid` у рендера канваса не нужен, но полезен
   способ узнать выбранное здание/камеру без калибровки (например, `window.__fireline?.camera` только в dev). Сейчас
   калибровка по полигону подсветки работает без правок прод-кода.
