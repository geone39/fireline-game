# Открытые вопросы

- **OQ-1** ✅ РЕШЕНО 2026-10-19 владельцем: пошаговый тактический бой на клеточной сетке; игрок командует своими юнитами (стрелять по зданию/юниту или перемещаться), ходы обороны делает ИИ (постройки и подкрепление сами). См. ADR-003, D-03.
- **OQ-2** ✅ РЕШЕНО 2026-10-19 владельцем (docs/variants/DECISIONS.md): S01, A01-lite, P01+P03, U01/U03, тон ироничный, рабочее название N05 «Плацдарм» (товарный знак — OQ-5).
- **OQ-7** (design → owner) Механика пошагового боя. Полная спека — `docs/design/battle-sim.md` (DESIGN-2). Решить до SIM-1; до ответа действуют ASSUMPTION ниже. **needs-owner** — то, что решает владелец; остальное — безопасное допущение дизайна, sim можно писать без ответа.
  - **ПРИНЯТО владельцем 2026-10-19 (рекомендации оркестратора):** 7.1 ap:1, ap:2 только у лёгкой пехоты и разведки; 7.5 без LOS в R1; 7.6 способность героя-стража и ПВО-зонтик эсминца вне R1; 7.7 строгая политика: клиентский результат с отклонёнными командами отклоняется, засчитывается серверный пересчёт; 7.8 позиции скрытых мин клиент в предпросмотре не видит (сервер не передаёт их в клиентский Snapshot; срабатывание не предсказывается на клиенте); 7.9 «Автоход» в R1 не делаем, лимит армии — по лагерям. Спеку `battle-sim.md` привести в соответствие (DESIGN-2b).
  - **OQ-7.1** Очки действий. ASSUMPTION: у юнита `ap` очков в ход (ключ `ap` в `content/troops.yaml`, по умолчанию 1), Move/Attack/Ability стоят по 1 AP; `Move` — любая длина до `move_cells` за 1 AP; заклинания AP не тратят. **needs-owner/balance:** у каких юнитов `ap: 2` (черновик: лёгкая пехота — `u_rifleman`, `u_dasher`), и нужен ли «ремень» AP на героя.
  - **OQ-7.2** Порядок. ASSUMPTION: игрок командует юнитами в любом порядке, затем фаза обороны: 1) триггеры бункера/героя-стража, 2) зоновые эффекты и проволока, 3) постройки по `EntityID`, 4) юниты обороны по `EntityID`, 5) конец хода. Цель постройки/юнита: минимум `(расстояние, текущее HP, EntityID)`. Кратчайший путь юнитов обороны — Дейкстра с детерминированным тайбрейком (`battle-sim.md` §7).
  - **OQ-7.3** ✅ РЕШЕНО 2026-10-19 владельцем: бой идёт, пока на поле есть выставленные юниты/техника атакующего (плюс 100% разрушения и `Retreat`), либо пока не истечёт **лимит времени — по умолчанию 5 минут реального времени** (число — ключ `battle.time_limit_s` в `content/battle.yaml`, balance может менять). Время — серверное и не входит в `sim` (детерминизм): сервер выдаёт тикет с `expires_at`, по истечении бой засчитывается по уже сыгранным ходам (как `Retreat`); `battle.max_turns` остаётся лишь техническим предохранителем конечности боя в sim (balance подбирает с запасом, чтобы 5 минут кончались раньше). Прежний ASSUMPTION: `battle.max_turns` в `content/battle.yaml` (число — решает balance/owner; в спеке не придумано). Окончание: 100%, нет юнитов, лимит ходов, `Retreat`. **needs-owner:** значение лимита (влияет на длину сессии на мобильном).
  - **OQ-7.4** Высадка. ASSUMPTION: фаза 0 без таймера, зона = клетки вне `build_zone` (кайма 2 клетки, `base_grid.yaml`), корабли — вода каймы; все юниты выставляются до `Start`, потом без пополнения; перевозчики выгружают пассажиров способностью; `u_paratrooper` — группа из 4 в пределах `paradrop_edge_cells` от края. Снято противоречие со старым правилом «footprint здания + 1 тайл» (raids-pvp): оно несовместимо с каймой шириной 2.
  - **OQ-7.5** Дальность/линия огня. ASSUMPTION: метрика Чебышёва, дальность в целых клетках (дробь YAML округляется вниз), **без LOS** — стены не блокируют стрельбу; в sim есть заглушка `LineOfFire`. **needs-owner:** нужна ли LOS (стены закрывают огонь) — тогда расширение спеки и больше тактики, но дороже UX.
  - **OQ-7.6** Заклинания/герои/корабли. ASSUMPTION: заклинания — зоны (Чебышёв) без AP, эффект по `turns(duration_s)`; герой — юнит с AP и способностью с кулдауном в ходах; корабли — по воде, береговые цели; способность героя-стража и «ПВО-зонтик» эсминца в R1 не реализуются. **needs-owner:** подтвердить вынос из R1; формат `ability.effect` в `heroes.yaml` (CONTENT-REQ).
  - **OQ-7.7** Реплей и ускорение. ASSUMPTION: реплей = журнал команд, события для анимации даёт ядро, «пропустить фазу обороны» — режим UI; сервер отклоняет `finish`, если в журнале есть отклонённые команды или нет завершения (`log_end`). **needs-owner:** строгая или мягкая политика отклонения.
  - **OQ-7.8** Скрытые ловушки. ASSUMPTION: в UI скрыты, но позиции есть в `Snapshot` (иначе нельзя предсказать результат на клиенте); радар их «вскрывает». **needs-owner:** ок ли, что клиент технически видит позиции мин (читерский оверлей), или передавать их только серверу и не предсказывать срабатывание на клиенте.
  - **OQ-7.9** Масса юнитов и мобильный ввод. ASSUMPTION: sim принимает только явные `Move`/`Attack`; «авто-ход» (макрос группы, «атаковать ближайшую») — клиентская фича, развёртываемая в явные команды. **needs-owner:** приоритет макросов для R1 и лимит размера армии (команды × ходы).
