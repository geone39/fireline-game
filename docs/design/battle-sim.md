# Боевое ядро (sim) — спецификация пошагового боя (DESIGN-2)

Статус: черновик под sim `0.2` (SIM-0). Основание: ADR-003 / D-03 (OQ-1 решён 2026-10-19). Заменяет realtime-версию (тик 100 мс, fixed-point 1000/тайл).
Договорённости по записи: **ASSUMPTION** — допущение дизайнера, действует до ответа; **needs-owner** — решает владелец (см. `docs/open-questions.md`, OQ-7.x); **CONTENT-REQ** — нужен новый ключ в `content/*.yaml` (запрос модулю `content`, список в §14).
Все числа здесь — **ключи контента**, а не значения. Числа в примерах (§12) — тестовая фикстура, не баланс.

---

## 1. Принципы

1. Бой = `(Snapshot, []Command, seed, ContentVersion)` → `Result`. Журнал команд = реплей (D-03, D-04).
2. Время измеряется **ходами**. Ход `t` = *фаза игрока* → *фаза обороны*. Тиков, секунд и дробных координат в sim нет.
3. Игрок командует **своими** юнитами, героем, заклинаниями. Оборона (постройки, гарнизон, герой-страж) действует сама по правилам §7. Защитник-человек в бою не участвует (D-02).
4. Только целые числа. Никаких `float`, `time`, `math/rand`, итерации по `map` в логике (AGENTS.md п.4).
5. Сервер авторитарен (D-05): клиент шлёт команды; результат считает сервер тем же ядром. Клиент использует WASM для предсказания и проверки легальности.
6. Случайности в правилах R1 **нет**. `seed` остаётся в контракте и в `StateHash`; использование `RNG` в правилах — только через `sim.RNG` и только после правки этой спеки.

## 2. Мир

### 2.1 Сетка
- Размер — `content/base_grid.yaml: grid {w,h}` (44×44). Клетка `Cell{X,Y int16}`, начало (0,0) слева сверху, X вправо, Y вниз.
- Слои: **земля** (INF, VEH), **воздух** (AIR), **вода** (SEA). В одной клетке — не более одной сущности на слой (воздух и земля могут делить клетку).
- Вода — клетки `maps.<id>.water` из `base_grid.yaml`. По воде ходят только SEA; на воде нет зданий (OQ-B1).
- `build_zone` из `base_grid.yaml` — зона построек; клетки вне неё (кайма) — **зона высадки** (§4).

### 2.2 Метрика
Везде одна метрика — **Чебышёва** (диагональ = 1): `cheb(a,b) = max(|ax-bx|, |ay-by|)`. Дальность, радиусы, сплэш, ауры. (OQ-7.5, ASSUMPTION.)
Расстояние до **постройки** = минимум `cheb` от клетки стрелка до любой клетки её footprint. Расстояние сущность↔сущность в 1 клетку = «вплотную» (включая диагональ).
Радиус из YAML с дробью (`4.5`, `1.6`, `3.5`) переводится в клетки **вниз** (`4`, `1`, `3`) при загрузке контента (§3.2); явный ключ `*_cells` имеет приоритет.

### 2.3 Проходимость (для наземных юнитов)
Клетка непроходима для земли, если: вне карты; вода; в footprint живой постройки любого типа (здания, активная оборона, **стены/заборы** `blocks: true`, декор, препятствия); для техники — `d_tank_trap` (`blocks: vehicles`); занята другой живой наземной сущностью (своей или чужой).
Проходима, но с эффектом: `d_wire` (`blocks: false`) — замедление пехоты и урон (§8.3).
Скрытые ловушки (`d_mine`, `d_spring_trap`) не блокируют; срабатывают при входе (§8.4).
Разрушенная постройка освобождает клетки сразу (обломков нет).
**Диагональный шаг** запрещён, если обе ортогональные соседние клетки непроходимы для данного юнита (нельзя протискиваться через «лесенку» стен). Иначе разрешён.
Воздух: границы карты — единственное ограничение; в клетку, где уже стоит другой воздушный юнит, входить нельзя.
Корабли: только клетки воды; в клетку другого корабля нельзя.

### 2.4 Сущности и порядок
- `EntityID uint32`, начинается с 1. Порядок присвоения (**канонический, нужен для детерминизма**):
  1. постройки защитника, отсортированные по `(Pos.Y, Pos.X, ID)` по возрастанию (порядок в `Snapshot` значения не имеет);
  2. гарнизонные юниты и герой-страж в порядке выдачи §7.2;
  3. юниты атакующего — в порядке принятых команд `Deploy` (фаза 0); порождённые во время боя (выгрузка, высвобождение гарнизона) получают следующий свободный id в порядке порождения.
- Все «обходы» логики идут по возрастанию `EntityID`. Сортировка стабильная; ничьи — по `EntityID`.

## 3. Статистика юнитов и построек

### 3.1 Что хранит контент
Источники: `content/troops.yaml`, `defences.yaml`, `heroes.yaml`, `buildings.yaml` (+ новый `content/battle.yaml`, §14). Поле `fav` в sim **не используется** (ИИ у юнитов игрока нет); оно — подсказка UI (иконка «любимая цель»).

### 3.2 Перевод в целые «за ход» (делается один раз при загрузке контента, целочисленно)
Входные величины YAML (`speed`, `range`, `dps` и т.п.) имеют не более одного знака после запятой; загрузчик читает их в **десятых** (`round(v*10)`), дальше — целые.
Обозначения: `T10 = battle.turn_s × 10` (CONTENT-REQ: `battle.turn_s`, секунд реального времени «в одном ходе» — лишь масштаб перевода). `Mhp[L]`, `Mdps[L]` — множители уровня в промилле: `M[1]=1000`, `M[n] = floor(M[n-1] × g / 1000)`, где `g` — рост за уровень в промилле (CONTENT-REQ: `level_growth` в yaml вместо комментариев: войска hp 1180 / dps 1160; оборона hp 1200 / dps 1170).

| Величина | Формула (целые, `int64`) | Явное переопределение в yaml |
|---|---|---|
| `max_hp(L)` | `floor(hp × Mhp[L] / 1000)` | — |
| `dmg(L)` — урон одного действия «атака» | `floor(dps10 × Mdps[L] × T10 / 100000)` | `attack_dmg` |
| `move_cells` | `max(1, floor(speed10 × T10 / 100))` (если `speed>0`) | `move_cells` |
| `range_cells` | `floor(range10 / 10)`; для `range: 0` — «ближний бой», эффективно **1** (вплотную) | `range_cells` |
| `splash_cells` | `floor(splash_r10 / 10)` | `splash_cells` |
| `min_range_cells` | `floor(min_range10 / 10)` | `min_range_cells` |
| `turns(s)` — секунды → ходы | `max(1, ceil(s10 / T10))` | `*_turns` |
| `heal(L)` за действие | `floor(heal_ps10 × T10 / 100)` | — |
| `ap` — очков действий в ход | ключ `ap`, по умолчанию **1** | — |

Один «выстрел» = одно действие `attack` = вся огневая работа юнита за ход. Это сознательное упрощение: темп стрельбы отдельно не моделируется (каждый атакующий компонент — 1 действие за очко действий).

## 4. Фазы боя

```
Фаза 0  РАЗВЁРТЫВАНИЕ (turn=0): Deploy*, Load*, затем Start
Ход 1…N   [Фаза игрока: Move/Attack/Ability/Cast в любом порядке … EndTurn] → [Фаза обороны (§7)]
Конец   по условию §10
```
`N = battle.max_turns` (CONTENT-REQ; OQ-7.3: лимит ходов — ASSUMPTION, число задаёт balance/owner, не придумано здесь).

### 4.1 Высадка (OQ-7.4, ASSUMPTION)
- Фаза 0 не расходует ходы и не запускает оборону. Нет таймера (клиентская «подготовка 30 с» — UX, sim её не знает).
- **Зона высадки** = клетки карты **вне** `build_zone` (2-клеточная кайма). *Противоречие с raids-pvp (старое «footprint+1») снято:* каймы шириной 2 при `build_zone` до границы хватает только при отсутствии зазора, поэтому берём кайму целиком.
- Наземные/воздушные юниты — на свободных клетках каймы (не вода). Корабли — на клетках воды каймы. Один юнит на слой в клетке.
- `Deploy{ID, Level, To}` берёт юнит из слота `Army` (счёт `Count` уменьшается). Герой — слот `Hero`, один, не более одного `Deploy` героя.
- **Десант `u_paratrooper`:** один `Deploy` ставит группу из 4 юнитов (стоимость housing как 4 слота). Цель — любая свободная клетка в пределах `paradrop_edge_cells` от края карты (CONTENT-REQ; в YAML «радиус 3 от края»), остальные три — на ближайших свободных клетках по кольцам `cheb` вокруг `To`, внутри кольца порядок `(Y, X)`. Если мест нет — остаток группы не ставится (команда отклоняется целиком).
- **Перевозчики** (`v_apc` `carries: 6`, `s_lander` `carries: 10`): `Load{Unit: пассажир, Target: перевозчик}` в фазе 0 — пассажир (только INF, ранее выставленный `Deploy` или взятый из `Army` на борту) на борт, клетку не занимает. Превышение `carries` — отклонить.
- Условие `Start`: выставлен хотя бы один юнит (иначе `Start` отклоняется; игрок может `Retreat`). После `Start` Deploy и Load запрещены (OQ-7.4: лимит армии — housing лагерей, проверяет сервер при формировании `Army`, sim не проверяет).
- Заклинания и герой в фазе 0 не применяются.

### 4.2 Фаза игрока
- Начало хода игрока `t`: каждому живому юниту атакующего `ap_left := ap`; кулдауны способностей `cd -= 1` (не ниже 0).
- Игрок подаёт любое число команд в любом порядке (OQ-7.2): на ход каждым юнитом — не более `ap` действий; заклинания — вне очков (§9.1).
- `EndTurn` завершает фазу игрока, запускает фазу обороны хода `t`. Если в журнале ход `t` сменился на `t+1` без `EndTurn`, sim считает `EndTurn` поданным неявно (команда `Turn` не убывает).
- Все действия применяются **немедленно** и последовательно (порядок в журнале = порядок разрешения).

## 5. Действия игрока

Одно действие стоит **1 AP** (кроме указанных). Очки не копятся между ходами.

| Действие | Команда | Условие | Эффект |
|---|---|---|---|
| Перемещение | `Move{Unit, Path}` | см. §5.1 | юнит идёт по `Path`; 1 AP независимо от длины |
| Атака | `Attack{Unit, Target}` | см. §5.2 | урон по §6 |
| Способность | `Ability{Unit, Kind, Target?, To?}` | §5.3 | разные |
| Заклинание | `Cast{ID, To}` | §9.1 | зона |
| Конец хода | `EndTurn{}` | — | запуск обороны |
| Отступление | `Retreat{}` | фаза 0 или игрока | конец боя (§10) |

### 5.1 Move
- `Path` — **явная** последовательность клеток после стартовой; каждая следующая — соседняя (8 направлений) к предыдущей (§2.3 диагональное правило). Явный путь избавляет sim от поиска пути для игрока и однозначно задаёт, по каким клеткам прошёл юнит (ловушки, проволока).
- Стоимость шага = `cost(cell)`: 1; для клетки с `d_wire` и юнита INF — `ceil(100 / (100 - slow_pct))` (при 50% → 2). Сумма стоимостей ≤ `move_cells` (+ бонус адреналина §9.2). Минимум 1 шаг.
- Все промежуточные клетки проходимы и свободны (сквозь своих нельзя — ASSUMPTION; воздух проходит сквозь всё), конечная свободна.
- **Прерывание:** на клетке сработавшей ловушки (§8.4) юнит останавливается, остаток пути отбрасывается, AP не возвращается.
- Юнит с `move_cells = 0` (стационарные) двигаться не может.
- Корабль: клетки воды; наземный перемещаться в воду не может.

### 5.2 Attack
Условия: юнит жив, `ap_left ≥ 1`, у юнита есть атака (`dmg > 0` или `burst > 0`); цель — **живая видимая** сущность обороны (постройка, стена, декор — **нельзя**, юнит гарнизона, герой-страж); не скрытая ловушка (мина/пружина, пока не вскрыта; **вскрыта** — если игрок взял разведку радара: поле `RevealedTraps` в `Snapshot`, ASSUMPTION; иначе недоступна как цель); дальность: `min_range_cells ≤ dist ≤ range_cells` (ближний бой: `dist == 1`). Линии огня нет (§6.4).
Ограничения по классам цели: наземный/воздушный урон атакующего бьёт любую цель обороны (ASSUMPTION: фильтров `vs` у юнитов нет); `u_breacher` и огнемёт — особые (§6.3).
Атака тратит 1 AP. Юнит без AP и без возможности действовать «ждёт» (ничего не делает; **пас** — отсутствие команд).

### 5.3 Ability
| Kind | Кто | Эффект | Цена |
|---|---|---|---|
| `heal` | `u_medic` (цель INF), `v_engineer` (цель VEH) | цель в `range_cells`, `+heal(L)` HP, не выше `max_hp`; сам себя нельзя | 1 AP |
| `jam` | `u_saboteur` | цель — постройка обороны с атакой, вплотную (`dist == 1`): `disabled` на `turns(jam_s)` (§7.5) | 1 AP |
| `unload` | `v_apc`, `s_lander` | высадить всех (или `Target` один) пассажиров; клетки — §5.4 | 1 AP перевозчика |
| `hero` | герой: `a_cover_fire`, `a_decoy_turret`, `a_vanish`, `a_bulwark` | эффект из `heroes.yaml ability.effect` (CONTENT-REQ); кулдаун `turns(cooldown_s)` | 1 AP героя |
Общее: способность недоступна при `cd > 0`; после применения `cd := turns(cooldown_s)`. Видов эффектов в R1 (`effect.kind`): `zone_damage` (как заклинание), `spawn_decoy` (сущность-приманка, хранит HP; оборона считает её целью), `stealth` (`turns`: недоступен как цель для обороны, пока не атаковал; бонус ×k к следующему выстрелу по цели из `vs_tag`), `buff_aura`. Подробности чисел — только в yaml.

### 5.4 Выгрузка
Пассажиры появляются на свободных проходимых клетках в `cheb ≤ 1` от перевозчика (для `s_lander` — только суша/не вода), порядок заполнения: по возрастанию `(Y, X)`; пассажиры — по порядку погрузки. Не поместившиеся остаются на борту. Выгруженные юниты `ap_left := 0` в этот ход.
**Гибель перевозчика:** пассажиры высаживаются тем же правилом в момент гибели с текущим HP; не нашедшие место — погибают. Корабль на воде: места только на суше; иначе пассажиры гибнут.

## 6. Урон

### 6.1 Базовое правило
`damage = dmg(L)` юнита-стрелка (целое). Модификаторы (целочисленно, в промилле):
`damage = floor(dmg × (1000 + Σbonus) / 1000)`, `bonus` — адреналин (`adrenaline_dmg_permille`), аура `h_commander` (`aura_dmg_permille`), `vs_mult` (опциональный блок юнита в yaml, напр. `{wire: 1500}`). Бонусы складываются, затем один `floor`. Отрицательных — нет (броня `armor_pct` в R1 отсутствует; ASSUMPTION).
Цель теряет `min(HP, damage)`; HP ≤ 0 → сущность уничтожена **сразу** (клетки освобождены, не может ходить/стрелять, не считается целью для следующих).

### 6.2 Сплэш (`splash_cells = r > 0`)
Центр — клетка основной цели (для постройки — ближайшая к стрелку клетка footprint). Все **вражеские** сущности (и сам прицел) с `dist(центр) ≤ r` получают `floor(damage × (100 − splash_falloff_pct × d / r) / 100)`, `d` — расстояние до центра (CONTENT-REQ: `battle.splash_falloff_pct`, в старой версии 40). Своих и нейтральных (декор) не задевает. Стены — обычные цели (бьются сплэшем).
«Конус» (`d_flame_trap`, `u_flamer`): в R1 = сплэш радиуса `splash_cells`/1 вокруг цели (ASSUMPTION; форма — только анимация).
Цепь `d_tesla` (`chain: k`): основная цель + до `k-1` следующих; каждая следующая — ближайшая (по `cheb`, ничья — `EntityID`) ещё не поражённая вражеская цель из `vs` в `chain_cells` (CONTENT-REQ) от предыдущей; урон каждой — полный.

### 6.3 Особые
- `u_breacher`: единственная атака — подрыв: цель вплотную; урон `burst` (×`wall_mult` по целям с `blocks` или проволоке) по цели и сплэшем `splash_cells` (CONTENT-REQ, по старой версии 1); юнит **уничтожается** после подрыва (учитывается как потеря).
- `u_saboteur`, `u_medic`, `v_engineer`: `dmg = 0` — только Ability.
- `u_drone` (AIR): бьёт вплотную (`range: 0`), пролетает над стенами; цели `vs` обороны с `AIR` (MG, ПВО) способны её бить.
- `s_gunboat`/`s_destroyer`: стреляют по любым целям обороны в дальности (в т.ч. береговым); по ним — `vs: SEA` (ПТ-пушка, береговая батарея). «ПВО-зонтик» `s_destroyer` в R1 **не реализуется** (вынесено из объёма, OQ-7.6).

### 6.4 Дальность и линия огня (OQ-7.5)
- ASSUMPTION R1: **без LOS**. Стены/здания блокируют движение, но **не стрельбу**. Любая цель в `[min, range]` по Чебышёву доступна.
- Задел: функция `LineOfFire(from, to) bool` существует в sim, возвращает `true`; вариант «LOS по Брезенхэму, блокируют стены/здания, кроме целей-концов» — расширение (needs-owner, OQ-7.5).

## 7. Фаза обороны (ИИ)

Выполняется целиком после `EndTurn`. Игрок в ней ничего не делает (UI проигрывает события, §11). Порядок шагов хода `t`:

1. **Триггеры.** Бункер(ы), герой-страж: высвобождение (§7.2).
2. **Зоновые эффекты хода.** Накопленные заклинания (airstrike/medkit, §9) отрабатывают свой шаг; проволока: каждый наземный INF-юнит атакующего на клетке `d_wire` получает `dot_dps × T10 / 10` (целое, floor); смерть — сразу.
3. **Активные постройки обороны** в порядке `EntityID`: выбирают цель, стреляют (§7.3).
4. **Юниты обороны** (гарнизон, герой-страж) в порядке `EntityID`: ИИ юнита (§7.4).
5. **Окончание хода:** уменьшить таймеры эффектов; если `turn == max_turns` → конец боя. Проверка условий завершения §10 выполняется **после каждого действия**, а не только здесь.

### 7.1 Кто стреляет
Постройка стреляет, если: жива, имеет `dps`, не `disabled`, не перегрета, ровно один раз за фазу. `d_bunker`, `d_jammer`, пассивные (`wire`, `fence`, …) — сами не стреляют. `AP` у построек = 1, потратить его можно только на выстрел.

### 7.2 Бункер и гарнизон
- `Snapshot.Garrison` раскладывается по бункерам в порядке `EntityID`: каждому до `garrison` юнитов по порядку списка. Лишние — теряются; без бункера гарнизон не появляется (ASSUMPTION).
- Бункер **высвобождает** всех своих юнитов в начале фазы обороны хода, если (а) он получил урон хоть раз или (б) атакующий юнит в `trigger_cells` от его footprint (CONTENT-REQ; по умолчанию = дальность стрелковых юнитов гарнизона). Юниты появляются на свободных проходимых клетках в `cheb ≤ 1` (кольцами, порядок `(Y,X)`); не нашедшие место ждут следующего хода. Новые `EntityID` — в порядке появления. В тот же ход они **действуют** (шаг 4).
- Герой-страж (`Snapshot.DefenderHero`, ASSUMPTION): стоит у `b_hq`; высвобождается по тому же триггеру (радиус от HQ). В R1 его способность не применяется (OQ-7.6).

### 7.3 Выбор цели постройки
Кандидаты — живые сущности **атакующего** слоя, чей класс ∈ `vs` построек, `min_range_cells ≤ dist ≤ range_cells`, не в дыме (§9.2: `c_smoke` — цели внутри зоны недоступны, кроме `dist ≤ 1`), не `stealth`.
Выбор — минимум по ключу `(dist, hp_current, EntityID)`. Основная цель получает `damage`; сплэш/цепь — §6.2. Миномёт `min_range` исключает близких.
**Перегрев** `d_flame_trap`: после `overheat_fire_turns` подряд выстрелов (CONTENT-REQ; в старой версии 6 с) — `cool_turns` без стрельбы; счётчик в `StateHash`.

### 7.4 ИИ юнита обороны
Те же `ap`, `move_cells`, `dmg`, `range_cells`, что у юнитов атакующего (ID из `troops.yaml`). Цели — любая сущность атакующего (по классу фильтров нет, ASSUMPTION), не `stealth`/не в дыме.
Алгоритм на юнит (по очкам действий, пока `ap_left > 0`):
1. Есть цель в дальности → атаковать (ключ как §7.3). Один AP.
2. Иначе — идти к ближайшей цели: считаем Дейкстру по проходимым клеткам от текущей (стоимость как §5.1; чужие юниты — препятствия; шаги упорядочены N,NE,E,SE,S,SW,W,NW; очередь по `(cost, cell_index=Y*W+X)`; при равных `cost` сохраняем первого родителя). Для каждой цели-кандидата — минимальная стоимость до клетки, с которой цель в дальности; выбираем цель с минимальной стоимостью, ничья — меньший `EntityID`; целевая клетка — минимум `(cost, cell_index)`. Идём по цепочке родителей на максимальную длину ≤ `move_cells`, оканчивая на свободной клетке. Нет пути — остаётся на месте.
3. Если после шага осталось AP и цель в дальности — атака (при `ap ≥ 2`).
Поводка/возвращения нет (ASSUMPTION: гарнизон преследует до смерти). Лечение/способности юнитов обороны не используются.

### 7.5 Помехи и отключение
- `disabled` (саботёр `jam`, ЭМИ `c_emp`) на постройке: не стреляет, не перегревается, не высвобождает (бункер) пока `disabled`; ставится как `expires_after_turn = t + turns − 1` (эффект активен в фазе игрока и обороне хода `t` … `t+turns−1`).
- `d_jammer`: если центр `Cast` (airstrike/EMP) находится в `cheb ≤ aura_r` от живого не-`disabled` генератора — эффект заклинания ×`(100 − jam_pct)/100` (урон/длительность, floor, ≥1); несколько генераторов **не складываются** (ASSUMPTION). CONTENT-REQ: `jam_pct` (в старой версии 50).

## 8. Стены, ловушки, препятствия

### 8.1 Стены и заборы
`blocks: true` — непроходимы; разрушаются как любые цели с `hp`; в процент разрушения не входят (§10.2). Для смысла «головоломки маршрута» игрок сам решает, бить ли стену, идти в обход или применять `u_breacher`/`c_breach`.
`c_breach` уничтожает все стены в круге/квадрате радиуса — §9.1.

### 8.2 Танковые ежи
`blocks: vehicles` — для VEH как стена; INF/AIR проходят. Цели для атаки (`hp`), в процент не входят.

### 8.3 Проволока
Проходима. INF: шаг стоит `cost` (§5.1); раз в фазу обороны урон (шаг 2). Бьётся как цель, в процент не входит. Огнемёт и т.п. — через `vs_mult`.

### 8.4 Скрытые ловушки
- `d_mine`: срабатывает при входе на клетку юнита класса из `vs` (INF/VEH; не AIR/SEA). Урон `burst` + сплэш `splash_cells` (всем **вражеским** к минёру сущностям, в т.ч. юнит-триггеру), уничтожается и убирается. Перевооружение — вне боя.
- `d_spring_trap`: срабатывает на INF с `max_hp ≤ max_hp_flung`; юнит перемещается в направлении, **противоположном** последнему шагу, на `fling_cells` (CONTENT-REQ) или до первого препятствия, на свободную проходимую клетку (ближайшую к цели по этому лучу); ловушка расходуется; остаток пути отбрасывается, AP не возвращается. Если юнит тяжелее — ловушка не срабатывает.
- Видимость: в UI скрыты (`Snapshot.RevealedTraps` из `b_radar`); sim знает их всегда. Скрытая ловушка не может быть целью `Attack`. **needs-owner** (OQ-7.8): передавать ли позиции скрытых ловушек клиенту (для WASM-проверки они нужны; в UI скрываются).
- Не входят в процент разрушения.

### 8.5 Декор и препятствия
Непроходимы, неуязвимы, не цели, не входят в процент (ASSUMPTION).

## 9. Заклинания, герои, техника, корабли

### 9.1 Заклинания (`Cast{ID, To}`)
- Из слотов `Spells` (`Count` уменьшается). Не тратят AP; не более `spells_per_turn` за ход (CONTENT-REQ; без ключа — без лимита, ASSUMPTION). `To` — любая клетка карты. Радиус `radius_cells` (`floor`), метрика §2.2 (квадрат).
- Эффекты длятся `turns(duration_s)` ходов (CONTENT-REQ: `duration_s` у `c_airstrike` — в тексте «за 4 с», у `c_medkit` — «12 с»); `expires_after_turn = t + turns − 1`; шаг эффекта отрабатывает в **фазе обороны** хода (шаг 2) каждого хода действия, при касте в фазе игрока — первый шаг отрабатывает в обороне того же хода.
- `c_airstrike`: за всё время `dmg_total` по каждой **вражеской** сущности в зоне (постройки, стены, юниты; без скрытых ловушек); урон равномерно по `turns`, остаток первому шагу. Не бьёт своих.
- `c_medkit`: `heal_total` своим INF в зоне, равномерно по `turns`.
- `c_smoke`: пока активна, юниты **атакующего** в зоне — не цель для обороны (§7.3), кроме `dist ≤ 1` до стрелка.
- `c_adrenaline` (+скорость/+урон, `duration`): **зона-эффект** — получают юниты атакующего, стоящие в зоне на момент каста (множество фиксируется по `EntityID`), бонус `adrenaline_move_permille` (к `move_cells`, floor, ≥ +1 клетка) и `adrenaline_dmg_permille` (CONTENT-REQ, в тексте 40% / 25%).
- `c_emp`: все постройки обороны в зоне `disabled` на `turns(duration_s)` (на момент каста; дальнейшее вхождение не учитывается).
- `c_breach`: все стены/заборы (`blocks: true`) в зоне уничтожаются сразу (в процент не входят).
- Джаммер уменьшает эффект airstrike/EMP (§7.5).

### 9.2 Герои
- Один на бой, `Deploy` в фазе 0, `ap` из `heroes.yaml` (по умолчанию 1), атака/движение как у юнита; способность §5.3. Смерть героя не уменьшает армию; `Result.HeroDamageTaken` (сумма полученного урона) — для таймера лечения (design/heroes.md).
- Аура `h_commander`: союзники в `aura_cells` (CONTENT-REQ) получают `aura_dmg_permille` и `aura_move_permille`; пересчитывается в момент действия (позиция командира на этот момент).

### 9.3 Техника
- `v_apc`: §5.3/5.4, `carries`. `v_tank`, `v_humvee`: обычные. `v_mortar` (самоходка): `range_cells` большой, `min_range_cells` отсутствует (ASSUMPTION: нет), сплэш. `v_engineer`: Ability `heal` для VEH.
- Узкие места: техника не проходит через `d_tank_trap`.

### 9.4 Корабли
- Двигаются по воде; на береговых картах (`maps.<id>.water`) зона высадки кораблей — вода каймы. Стреляют по берегу в дальности. `s_lander` перевозит INF (§4.1), выгрузка на соседнюю сушу.
- Цели кораблей для обороны: `vs: SEA` (`d_at_cannon`, `d_coastal`). Корабли обороны (патруль) из `Snapshot` — R1: нет (ASSUMPTION; снимок содержит только постройки и гарнизон).

## 10. Завершение и результат

### 10.1 Условия окончания (проверяются после каждой команды/действия/выстрела)
1. `full_destruction`: уничтожены все засчитываемые постройки (100%).
2. `no_units`: у атакующего не осталось живых юнитов (включая героя и находящихся на борту перевозчика) — немедленно.
3. `turn_limit`: окончен ход `max_turns` (после обороны хода `max_turns`).
4. `retreat`: команда `Retreat`.
5. `log_end`: журнал исчерпан до окончания (трактуется как `Retreat`, ASSUMPTION; сервер **не** принимает такие реплеи как валидные — **needs-owner**, OQ-7.7).

Если бой закончился, последующие команды отклоняются (`battle_over`).

### 10.2 Процент разрушения и звёзды
- **Засчитываемые** постройки: все из `Snapshot.Buildings`, кроме стен/заборов/ежей/проволоки (`passive_obstacles`), мин/ловушек, декора, препятствий. Включая `b_hq`, ресурсные, склады, казармы, оборону.
- Вес постройки = `destruction_weight` (CONTENT-REQ; по умолчанию 1). `total = Σ weight`, `done = Σ weight(destroyed)`.
- `Destruction = floor(100 × done / total)` (0..100; `total == 0` → 0).
- Звёзды (флаги): ★ HQ — уничтожен `b_hq`; ★ Half — `2 × done ≥ total`; ★ Full — `done == total`. `Stars = Σ`. Полный разрыв HQ при `done == total` даёт все три.
- Разрушенная постройка = HP ≤ 0 хоть раз; восстановления нет.

### 10.3 LootBasis
Для модуля economy; сортированный список, без `map`:
`Storages []StorageHit{EntityID, ContentID, Level, DamagePermille}` — по всем `b_vault`, `b_fuel_tank`, `b_alloy_depot` (`DamagePermille = floor(1000 × (max_hp − hp_end) / max_hp)`, 1000 если уничтожено); `PercentDestroyed` = `Destruction`; `Stars`. Формулы выдачи — `docs/design/raids-pvp.md`, `content/economy.yaml: raids`.

### 10.4 Прочие поля результата
Потери армии (`UnitsLost` по слотам), расход заклинаний (`SpellsUsed`), `HeroDamageTaken`, `HeroSurvived`, `TurnsUsed` (число начатых игроком ходов; в `retreat` в фазе 0 — 0), `EndReason`, `Rejected`, `EngineVersion`, `StateHash`.

## 11. Детерминизм и реплей

1. **Вход.** `Snapshot` (с нормализованным порядком §2.4) + `[]Command` + `seed` + `ContentVersion`. Нет «сейчас», нет окружения.
2. **Журнал.** Команды идут в порядке подачи; `Command.Turn` (0 или 1…N) **не убывает**; несоответствие → `bad_turn` (отклонение). Реплей = тот же журнал; шаг «пропустить фазу обороны» (OQ-7.7) — UI-режим, на результат не влияет.
3. **Отклонение.** Нелегальная команда **не меняет состояние**, добавляет в `Result.Rejected` запись `{Index, Code}`. Коды: `bad_phase, bad_turn, unknown_entity, not_owner, no_ap, cooldown, bad_path, path_cost, out_of_zone, cell_occupied, out_of_range, below_min_range, invalid_target, capacity, no_stock, hero_limit, battle_over`. Политика: честный клиент через WASM не шлёт нелегальных команд, поэтому сервер **отвергает `finish`, если `Rejected` не пуст** (ASSUMPTION; контракт сервера — отдельно).
4. **События для анимации.** Ядро даёт `Battle.Apply(cmd) → []Event` (см. §13.3): `Moved, Attacked{dmg}, Killed, Destroyed, TrapTriggered, SpellCast, EffectTick, Healed, Released, TurnEnded, BattleEnded`. События — функция состояния; в `StateHash` не входят.
5. **StateHash** (`xxhash64`, little-endian): `turn`, `phase`, `EntityID` порядок: для каждой живой/мёртвой сущности по возрастанию id — `id, kind, content_id, level, owner, cell, hp, ap_left, cd, effects(sorted by kind, expires), heat`; затем флаги `destroyed(buildings)`, `RNG.s`, счётчики `Rejected`.
6. **Запреты.** `float`, `time`, `math/rand`, итерация по `map`; параллелизм в правилах; платформо-зависимые округления — только целочисленные `floor/ceil` по спеке. Загрузчик читает десятые как `round(v×10)` (значения YAML с ≤1 знаком).
7. **Версии.** `EngineVersion` и `ContentVersion` в реплее; несовпадение → реплей считается старой версией движком той версии (политика хранения — сервер).
8. **Тесты.** Golden: `testdata/replays/G01…` (эталонные базы HQ1…HQ10); побитовый `StateHash` на CI для native и WASM; property «любая корректная серия команд даёт один результат при перестановке `Snapshot.Buildings`»; фазз команд (не падает, детерминирован); бенчмарк: полный бой (30 ходов, 120 юнитов, 150 построек) ≤ `battle.bench_ms` (CONTENT-REQ/CI-ключ, не в правилах).

## 12. Примеры

> Фикстура F01 (тест, **не баланс**): карта 44×44 `plain`, `battle.max_turns=30`; явные переопределения:
> `u_rifleman`: hp 50, ap 2, move 3, range 4, dmg 10. `u_brawler`: hp 100, ap 1, move 4, ближний бой (1), dmg 30.
> Постройки: `d_mg_nest` (2×2) в (12,10), hp 60, dmg 20, range 7, vs [INF]; `b_hq` (4×4) в (20,10). Засчитываемых построек 2.
> EntityID: гнездо = 1, штаб = 2 (порядок `(Y,X,ID)`), стрелок = 3, штурмовик = 4 (по порядку Deploy).

Журнал (сокращённо):
```
t0: Deploy{u_rifleman, L1, (1,10)}  Deploy{u_brawler, L1, (1,12)}  Start
t1: Move{3, [(2,10),(3,10),(4,10)]}   Move{4, [(2,12),(3,12),(4,12),(5,12)]}   EndTurn
t2: Move{3, [(5,10),(6,10),(7,10)]}   Move{4, [(6,12),(7,12),(8,12),(9,12)]}   EndTurn
t3: Move{3, [(8,10)]}  Attack{3→1}   Move{4, [(10,12),(11,12)]}   EndTurn
t4: Attack{4→1}  Attack{3→1}  Attack{3→1}   Retreat
```
| Ход | Игрок | Оборона (гнездо №1: цели `INF` в ≤7, ключ `(dist,hp,id)`) | Состояние |
|---|---|---|---|
| 0 | Deploy ×2, `Start` | — | юниты в кайме (x<2) |
| 1 | стрелок → (4,10), штурмовик → (5,12) | штурмовик на (5,12): dist до клетки (12,11) = 7 ≤ 7; стрелок (4,10): dist 8 — вне. Бьёт №4 на 20 | №4: 80 |
| 2 | стрелок → (7,10) [dist 5], штурмовик → (9,12) [dist 3] | оба в зоне; ближе №4 (3<5) → №4 −20 | №4: 60 |
| 3 | стрелок → (8,10) (1 AP), `Attack` №1 (dist 4 ≤ 4): гнездо 60→50; штурмовик → (11,12) | №4 вплотную (dist 1) vs №3 (dist 4) → №4 −20 | №4: 40, гнездо 50 |
| 4 | штурмовик вплотную: 50→20; стрелок 2 атаки: 20→10→0 — **гнездо разрушено** | гнездо мертво → стреляет нечем; игрок `Retreat` | done=1, total=2 |
Результат: `Destruction=50`, `Stars=1` (★Half; штаб цел), `HQDestroyed=false`, `TurnsUsed=4`, `EndReason=retreat`, `UnitsLost=[]`, `Rejected=[]`.

**Мини-примеры (отдельные фикстуры):**
- *Стена и подрывник.* `Attack{breacher → d_wall}`: `burst × wall_mult` по стене и по стенам в `splash_cells` вокруг, подрывник уничтожен. Клетки стен освобождаются — теперь они проходимы.
- *Мина.* `Move{Path:[A,B,C,D]}`: юнит INF на `C` — `d_mine`. Движение прекращено на `C`; взрыв `burst` + сплэш; `D` отброшена; AP потрачено.
- *БТР.* `Ability{unload}` у `v_apc`: 6 пассажиров на свободные клетки в `cheb≤1` по `(Y,X)`; у них `ap_left=0` в этот ход.
- *Саботёр.* Подходит вплотную к `d_mortar`, `Ability{jam}`: миномёт `disabled` на `turns(jam_s)`; в фазе обороны не стреляет.

## 13. Задел под контракт sim 0.2 (SIM-0)

### 13.1 Команда
```go
type Cell struct{ X, Y int16 }
type EntityID uint32

type Command struct {
    Turn   int       // 0 = развёртывание; 1…MaxTurns
    Op     Op        // Deploy, Load, Start, Move, Attack, Ability, Cast, EndTurn, Retreat
    Unit   EntityID  // актёр (Move, Attack, Ability); для Load — пассажир
    Target EntityID  // Attack, Ability(heal/jam), Load(перевозчик)
    ID     string    // Deploy: слот Army/Hero; Cast: заклинание; Ability: Kind
    Level  int       // Deploy
    To     Cell      // Deploy, Cast, Ability(при необходимости)
    Path   []Cell    // Move: клетки после стартовой
}
// Op: OpDeploy, OpLoad, OpStart, OpMove, OpAttack, OpAbility, OpCast, OpEndTurn, OpRetreat
```
`OpHeroAbility` из 0.1 заменяется `OpAbility`. `Tick` удаляется, `Pos Vec` → `Cell`.

### 13.2 Константы и типы
Убираются `TickMs`, `MaxTicks`, `TileUnits`, `Vec` (fixed-point). `MaxTurns` берётся из content (`battle.max_turns`), не из кода. `PlacedBuilding.Pos` → `Cell`. `Snapshot` дополняется: `DefenderHero string`, `RevealedTraps []EntityID`/клетки, `Map string` (вода), `Seed` остаётся аргументом `Run`.

### 13.3 Результат
```go
type Result struct {
    Stars, Destruction int
    StarFlags uint8              // бит0 HQ, бит1 Half, бит2 Full
    HQDestroyed bool
    TurnsUsed int
    EndReason EndReason          // FullDestruction, NoUnits, TurnLimit, Retreat, LogEnd
    LootBasis LootBasis          // Storages []StorageHit (sorted), PercentDestroyed, Stars
    UnitsLost  []SlotCount       // {ID, Level, Count}, sorted by (ID, Level)
    SpellsUsed []SlotCount
    HeroDamageTaken int
    HeroSurvived   bool
    Rejected []Rejection         // {Index int, Code RejectCode}
    EngineVersion string
    StateHash uint64
}
type Event struct{ Kind EventKind; Actor, Target EntityID; Cell Cell; Value int }
```

## 15. User stories и Acceptance

**US-B1 Высадка.** Как атакующий я расставляю армию на кайме без таймера боя, чтобы подготовить штурм. 
*AC:* юниты только на клетках вне `build_zone`; корабли — только в воде; герой — один; `Start` без юнитов отклоняется; после `Start` Deploy отклоняется.

**US-B2 Ход.** Как игрок я за ход командую каждым юнитом (двигаться или стрелять), чтобы управлять тактикой.
*AC:* юнит с `ap=1` не может выполнить и Move, и Attack за ход (`no_ap`); с `ap=2` — может в любом порядке; Move длиннее `move_cells` или через непроходимую клетку отклоняется (`bad_path`/`path_cost`); `EndTurn` запускает оборону.

**US-B3 Дальность.** Я вижу, куда достаёт юнит. 
*AC:* `Attack` вне `[min_range, range]` отклоняется; стены не блокируют стрельбу (R1); мёртвые цели не выбираются.

**US-B4 Оборона думает сама.** Защита стреляет без игрока по правилу `(dist,hp,id)`.
*AC:* один и тот же ход даёт одинаковые цели при перестановке `Snapshot.Buildings`; джам/ЭМИ отключают стрельбу; мина срабатывает однократно; бункер высвобождает гарнизон по триггеру; гарнизон идёт кратчайшим путём по тайбрейку §7.4.

**US-B5 Стены и ловушки.** Стены блокируют ход, пока целы; проволока замедляет INF и ранит; мина прерывает движение.
*AC:* diag-«лесенка» не пропускает; танковый ёж пропускает INF; разрушенная стена освобождает клетку в тот же момент.

**US-B6 Заклинания/герои/техника/корабли.** Support calls и способности работают по §9.
*AC:* airstrike не бьёт своих; dmg_total делится на `turns`; EMP отключает постройки; джаммер ослабляет эффект; выгрузка БТР/десантного катера и гибель перевозчика — по §5.4; флот плавает только по воде.

**US-B7 Итог.** Я вижу звёзды, % и потери.
*AC:* `Destruction=floor(100·done/total)`; ★Half ⇔ `2·done≥total`; ★Full ⇔ `done==total`; стены/ловушки/декор не в %; `Storages` отсортированы по `EntityID`.

**US-B8 Реплей.** Любой бой воспроизводится по журналу бит-в-бит. 
*AC:* для 1000 золотых реплеев `StateHash` совпадает на сервере и в WASM; `Rejected` непуст → сервер отклоняет `finish`; событий достаточно для пошаговой анимации и «пропустить фазу обороны».

## 16. Что не охвачено (R1)
Туман войны, броня (`armor_pct`), LOS, способности героя-стража, корабли обороны, поводок гарнизона, авто-ход для групп (макрос «авто-ход» на клиенте: клиент разворачивает в явные `Move/Attack`, sim их не знает — **needs-owner**, OQ-7.9).
