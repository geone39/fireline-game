# CHANGELOG `server-core`

## Unreleased
- SERVER-5 (#105): `army.Mount` подключён: `GET /v1/army`, `POST /v1/army/{train,cancel,speedup}`, `GET /v1/lab`, `POST /v1/lab/{research,cancel,speedup}` внутри авторизованной группы (Bearer, Idempotency-Key, rate limit, `X-Content-Version`, `server_time`/`content_version`, общий формат ошибок). `cmd/api` собирает `ArmyModule` (БД, `economy.Ledger`, `content/{army,troops,buildings,research}.yaml`).
- Стартовая раскладка нового игрока читается из `content/start_layout.yaml` (HQ L1 + готовый `b_camp`), без файла (тесты) — HQ по центру. Стартовая армия: `start_army` выдаётся в транзакции гостя только при `start_army_auto_grant: true` (сейчас `false`, OQ-ARMY-8), идемпотентно через метку `players.tutorial`; исследования не выдаются.
- Туториал: первый успешно поставленный в очередь заказ армии игрока завершается бесплатно один раз (`tutorial.free_finish_first_order`): после `POST /army/train` gateway вызывает `Service.Speedup` с ledger-обёрткой, не списывающей gems, и подменяет тело ответа этого запроса состоянием армии после завершения; повтор ключа отдаёт сохранённый ответ. Первое исследование не бесплатно.
- migrations: `00005_player_tutorial` (аддитивная) — `players.tutorial jsonb NOT NULL DEFAULT '{}'` (одноразовые метки `free_finish_used`, `start_army_granted`); `db.Store.ClaimTutorialMark/ReleaseTutorialMark`.
- `GET /v1/me`: `army.pools.<pool>.{used,capacity}` и `lab.{level, active:{node_id,finish_at}|null}`.
- contract-change (отдельный коммит, на утверждение владельцем): формы `/v1/army*`, `/v1/lab*`, `me.army`, `me.lab` и коды ошибок в `docs/03-api.md`.
- ASSUMPTION: уже созданные гости остаются со старой раскладкой (только HQ) — `base_state` пишется `ON CONFLICT DO NOTHING`, миграции данных нет (до релиза реальных игроков нет). Метка `free_finish_used` берётся до ускорения и снимается при ошибке; падение процесса между ними оставляет игрока без подарка (безопасная сторона). SSE `training_done`/`research_done` не сделан.
- SERVER-4: migrations `00004_army_research` (аддитивная) — `army(player_id, unit_id, level, count)` PK(player_id, unit_id, level), `CHECK level >= 1`, `count >= 0`; `research(player_id, node_id, state, finish_at)` PK(player_id, node_id), `state IN ('researching','done')`, `finish_at` обязателен при `researching`; FK на `players` ON DELETE CASCADE; индекс `timers(player_id, kind)`. Интеграционные тесты — `server/db/army_research_test.go` (testcontainers).
- timers: `kind='train'|'research'` не требуют изменения схемы (kind — text, детали в `payload` jsonb); `timers(finish_at)` уже есть.
- ASSUMPTION: состояния research — только `researching`/`done` (очереди исследований нет); `finish_at` у `done` может быть NULL; `count = 0` разрешён (строка не удаляется при нулевом остатке). Формат `payload` у train-таймеров (`building_id`, `count`, `level`) — за ARMY-1.
- не сделано: логика армии/лаборатории (ARMY-1/2), HTTP (SERVER-5).
- SERVER-3: `base.Mount` подключён под `/v1/base` (`GET /base`, `POST /base/commands`, `PUT /base/layout`) внутри авторизованной группы: Bearer, Idempotency-Key, rate limit, `X-Content-Version`; `server_time`/`content_version` и формат ошибок общие. `X-Content-Version` теперь ставится middleware на всех авторизованных ответах.
- migrations: `00003_defence_snapshots` (OQ-B7) — `defence_snapshots` по docs/04-data-model.md, `UNIQUE(player_id, base_version)`, иммутабельна (триггер на UPDATE). `SnapshotSink` реализован через `db.Store.InsertSnapshot` в транзакции `PUT /v1/base/layout`.
- auth: `Service.Provision` — хук в той же транзакции, что и upsert гостя; `cmd/api` подключает `BaseModule.Provision` = стартовая `base_state` + `Ledger.GrantStartTx` (OQ-E4). Ошибка откатывает создание игрока (атомарно); повторный логин идемпотентен и «долечивает» ранее созданных гостей.
- `GET /v1/me`: `builders` теперь из base (по слоту `{id:"bN", busy_until, target_id}`).
- `cmd/api` читает `building_costs.yaml` (`LoadPriceBook`): без файла (ECON-4) сервер не стартует. Интеграционные тесты используют фикстуру PriceBook и от файла не зависят.
- ASSUMPTION: стартовая раскладка — только HQ L1 по центру сетки (в content её нет, OQ-S6); `InitBase` не имеет tx-варианта, поэтому тот же INSERT выполняется в `Provision`.
- contract-change (отдельный коммит, на утверждение владельцем): формы ответов `/v1/base*` в `docs/03-api.md`.
- SERVER-2: `POST /v1/auth/refresh` (ротация: старый jti revoked атомарно, повтор отозванного/просроченного/неизвестного -> `unauthorized`); закрывает OQ-S1/S2 по реализации.
- gateway: карта статусов по docs/03-api.md (`invalid` всегда 400, в т.ч. неверный метод и слишком большое тело); `X-Content-Version` проверяется и на GET; `X-Content-Version` в заголовке каждого ответа.
- migrations: `00002_collector_pools` (OQ-E1) — аддитивная, `collector_pools(player_id, resource, amount, updated_at)`, PK(player_id, resource), CASCADE по игроку.
- `GET /v1/me`: поле `builders` (пока пустой список; данные придут из base, OQ-S3).
